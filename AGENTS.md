# AGENTS.md: Snapforge Lab

Read `CLAUDE.md` first: the offers, prices, identity and copy rules there are binding. This file adds the
engineering conventions and approval boundaries for any agent or contributor working in this repo.
Setup, layout and deploy steps are in `README.md`.

## Repo map
- `public/`: static site (Cloudflare Worker `proud-truth-105e`). Hand-written HTML; guides, `sitemap.xml` and
  `llms.txt` are generated by `python3 scripts/build.py`.
- `workers/mcp/`: the only backend (`mcp.snapforgelab.com`). `worker.js` routes, `deep-scan.js` scanner.
  `_worker.js` is GENERATED (`node build-pages-worker.mjs`): never edit it by hand.
- `docs/`: French, not deployed. `.claude/`: agent prompts; never edit `.claude/settings.json`.

## Branches and deploy
- `claude/awesome-faraday-f1lckc` is production: a merge or push there deploys. Never push to it directly;
  open a PR against it and wait for the owner to merge. Never force-push.
- One PR = one purpose, small enough to review in one sitting, CI green, and a short browser recording for
  any UI flow.

## Checks (CI runs the first three; all must pass before a PR)
- `cd workers/mcp && npm test`
- `cd workers/mcp && node build-pages-worker.mjs && git diff --exit-code _worker.js`
- `python3 scripts/build.py && git status --porcelain public` is empty
- For page changes, the site checks in `CLAUDE.md` (Playwright at 390 and 1280 px, JSON-LD, FAQ match, links).

## Boundaries: ask the owner first
- Prices, offer names, guarantees or the offer ladder.
- Payment or checkout code, payment webhooks, amounts.
- Auth, ownership verification, report access tokens.
- Database schemas, or any new binding in `wrangler.toml` / `wrangler.jsonc`.
- New third-party services, new npm dependencies, or paid Cloudflare features (free plan is the default).
- Production environment variables and secrets.
- Merging any PR.

## Scanner rules (security and legal)
- `check_app` (public MCP tool) stays surface-only: it never scans JS bundles. Its name, schema and annotations
  are frozen.
- Deep scans are read-only: GET only, no login, no writes, no form submits, and only the target's own public
  anon key against its own Supabase project. Keep the caps in `LIMITS` (`deep-scan.js`).
- Recurring scans run only on apps whose ownership has been verified.
- Never store, log or return table rows, file names inside buckets, or full secrets; mask secrets to the last
  4 characters. No `console.log` of scan data.

## Code conventions
- Plain JavaScript ES modules, no build step, no framework, no TypeScript; Workers runtime APIs only.
- Tests are plain Node scripts (`test-*.mjs`) with an injected `fetchImpl`: no network in tests.
- Secrets only through `env.*`. Every new variable goes in `workers/mcp/.env.example` and the README deploy
  steps in the same PR.
- Webhooks: verify the signature before trusting the body, and make handlers idempotent on the provider's
  event id.
- Money: integer cents, explicit currency, price decided on the server, never by the client.

## Escalation
- Stop and ask the owner when a boundary above applies, when the task is ambiguous, or after 2 failed
  attempts at the same command or test.
