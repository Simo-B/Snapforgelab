Replit database connection errors in production: how to fix them

By Simo, founder of Snapforge Lab · Updated Oct 16, 2026 · 4 min read

Short answer

  • Read the exact error first: "not set", "endpoint has been disabled", "SSL", "too many connections" and "relation does not exist" have different fixes.
  • A paused database is unpaused from the Database pane, for Development and Production. A conflicting DATABASE_URL secret can hide that button.
  • Use one shared connection pool per process, and run migrations against production before you publish.

The published app loads, then every page that touches data fails. Or publishing itself stops with DATABASE_URL environment variable is not set. Database errors in production look alike from the outside, but the message in the logs tells you which of five problems you have. Here is each one with its fix.

Symptoms

  • DATABASE_URL environment variable is not set at publish or startup.
  • The endpoint has been disabled or a frozen database.
  • connection requires SSL, self-signed certificate or ECONNREFUSED.
  • remaining connection slots are reserved, too many connections or connection pool exhausted under load.
  • relation "users" does not exist only in production.

Likely causes

  1. The deployment has no DATABASE_URL, or it points to the development database.
  2. The database compute endpoint was paused (Replit's help center names an unpaid invoice or a transient pause during publishing).
  3. An external Postgres (Neon, Supabase and others) requires SSL and the connection string or client does not use it.
  4. The code opens a new connection or pool per request instead of sharing one.
  5. Tables were created in development but migrations never ran on production.

Step-by-step fix

1. Copy the exact error

Open the deployment logs and copy the first database error with its stack trace. Match it to the steps below instead of trying every fix at once.

2. "Not set": check DATABASE_URL

In the Database pane, confirm a production database exists. Then check the deployment secrets: the published app must get the production connection string. If you also defined your own DATABASE_URL secret, compare it with the value in the Database pane. A stale one overrides the right one.

3. "Endpoint disabled": unpause

Replit's help center gives the steps: open the Database pane, select Development and click Unpause database if shown, then switch to Production and do the same. If the button is missing, a conflicting DATABASE_URL secret is the usual reason. Fix or remove it, refresh and check again. Pay any open invoice so it does not recur.

4. SSL errors: enable SSL for external Postgres

Hosted Postgres providers usually require encrypted connections. Use the connection string they give you (often with sslmode=require) and do not turn certificate checks off globally to make an error disappear.

5. Pool errors: share one pool

Create the pool once when the server starts and import it everywhere. Close any client you check out manually.

// db.ts: created once per process
import { Pool } from "pg";
export const pool = new Pool({ connectionString: process.env.DATABASE_URL, max: 10 });

// in a route: use the shared pool, never `new Pool()` here
const { rows } = await pool.query("select * from orders where user_id = $1", [userId]);

6. "Relation does not exist": run migrations on production

Apply your schema to the production database before or during publish, for example by running drizzle-kit migrate in the build step. See database migrations in production.

How to verify the fix

  • Deployment logs show a successful database connection at startup and no errors during a full user journey.
  • The Production view of the Database pane shows the expected tables and new rows created from the live app.
  • A quick load test (a few dozen parallel requests) does not produce pool or connection-limit errors.

FAQ

Why does my Replit app say DATABASE_URL is not set only after publishing?

The published app reads the deployment's environment, not your workspace. Check that a production database exists and that the deployment gets its connection string, without a stale DATABASE_URL secret overriding it.

What does "endpoint has been disabled" mean on Replit?

Replit's help center explains that the database compute endpoint was paused. Unpause it from the Database pane for Development and Production; if the button is missing, check for a conflicting DATABASE_URL secret.

How many database connections should my app use?

Use one shared pool per process with a modest maximum. Opening a new connection per request is the most common cause of pool exhausted errors.
