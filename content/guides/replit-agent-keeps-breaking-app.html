You ask Agent to fix a bug. It fixes it and breaks the login. You ask it to fix the login. The original bug comes back. Twenty messages later the app is worse than when you started, and the credit bill has quietly grown. This guide is how to get out of that loop.

Why the loop happens

  • The real cause is somewhere else. A missing secret in production, a database column that doesn't exist, a package version conflict. Agent keeps editing the file where the error appears, not where it starts.
  • Fixes pile up. Each attempt adds code instead of replacing the broken code. After a few rounds there are two or three competing versions of the same logic, and some of it never runs.
  • Context drifts. A long conversation carries early wrong assumptions forward.
  • Vague prompts. "It's still broken" gives Agent nothing new to work with, so it guesses.

Step 1: Stop and roll back

Stop sending messages. Find the last point where the app worked and roll back to it. Replit lets you roll back to a checkpoint from the Agent tab and the History view, which restores the project files and Agent's context to that moment. Agent also creates checkpoints before attempting fixes for critical issues, so a good one may already exist.

Careful with data: by default a rollback does not change your database. If Agent changed the schema or data during the loop, decide deliberately whether to include the database in the rollback. Your production database is separate and not touched by Agent.

Step 2: Diagnose before you prompt

Spend five minutes finding facts Agent can use:

  1. Get the exact error. Copy it from the console, the Shell, or the browser DevTools Console and Network tabs.
  2. Find when it happens. Which page, which button, which user?
  3. Check the usual suspects: is a secret missing? Did the database schema change? Does it work in the workspace but not in the published app?

Step 3: One bug, one precise request

Start a fresh conversation and use a structure like this:

Bug: Saving an invoice fails with "column due_date does not exist".
Where: POST /api/invoices, file server/routes/invoices.ts
Expected: the invoice saves and appears in the list.
Already checked: the column exists in the dev database schema file.
Constraints: don't change the login flow or the invoice list page.
First, explain the cause. Don't write code until I confirm.

Asking for the diagnosis first (or using a planning mode where available) avoids paying for code built on a wrong guess.

Step 4: Prevent the next loop

  • Commit or checkpoint when it works. Name good states so you can find them later.
  • Change one thing at a time. Large "build me the whole billing system" prompts create large blast radiuses.
  • Protect critical flows. Keep a two-minute manual test for login, the main workflow and payments, and run it after each change.
  • Watch spend. Set spending notifications and review usage weekly. See 12 ways to cut your Replit Agent bill.

When to call a developer

Bring in a human when the same bug survives two or three rollback cycles, when the issue touches authentication, payments or customer data, or when you're about to launch to real users. An experienced developer can usually find the root cause in the code faster than another twenty prompts, and for less than the credits they cost.
